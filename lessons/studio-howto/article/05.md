## Egatari ファイルとして保存する

できあがったものは、**Egatari ファイル**（`.ega.html`）として保存する。1 つのファイルの中に、スライド・台本・音声がすべて入る。

- **ファイル ▾ → 保存：** 開いているファイルに書き直す。Safari や Firefox では、保存先を聞くか、ダウンロードになる
- **ファイル ▾ → 名前を付けて保存…：** 名前や場所を変えて保存する。**新しいファイルとして保存する** に印を付けると、元のファイルとは別のものとして記録される。元のファイルの作成者やクレジットは残る

**ファイル ▾** の後ろに ● が付いているときは、まだ保存していない変更がある。

保存のしかたは 2 通りあり、Studio が自分で選ぶ。台本や音声だけを直したときは、スライドをビルドし直さずに、変わった所だけを書く。スライドを直したときは、ファイルの全体をビルドし直す。ビルドし直す前には、「編集していないスライドも、見え方が変わることがあります」と確かめる。

:::{figure} images/portable-save-menu.png
:label: fig-save-menu
:alt: ファイルのメニューが開き、新規作成、開く、保存、名前を付けて保存、エクスポートなどが並ぶ
ファイル ▾ のメニュー
:::

(sec-w5eykx)=
## 再生専用のファイル

受け取る人に渡すのは、**再生専用**のコピーだ。再生専用のファイルは、スライドと音声だけを持ち、編集はできない。

**ファイル ▾ → エクスポート ▸ → 参加者用（再生専用）…** を選び、**エクスポート…** を押して保存する。ファイルの名前は `○○.play.ega.html` になる。

受け取った人には、「ダウンロードしてから、ブラウザで開いてください」と伝える。Chrome・Edge・Safari・Firefox のどれでも、ネットにつながっていなくても再生できる。

- Google ドライブや Classroom のプレビューでは、スライドは動かない。ダウンロードしてから開いてもらう
- iPhone・iPad では、「ファイル」アプリの中では動かない。Egatari Viewer（viewer.egatari.org）で開くよう案内する
- 配る前に、自分のでない PC で、受け取る人と同じやり方で開き、音声付きで 1 枚再生しておく

編集できる元の Egatari ファイルは、自分で取っておく。再生専用のファイルからは直せない。

(sec-zkuigt)=
## 権利の表示

Egatari ファイルには、題名・作成者・著作権・ライセンス・クレジットを書いておける。プレーヤーの **ファイルの情報** に出る。

自分で作ったファイルを初めて保存するときは、「**このファイルは、あなたが作ったものですか。**」と聞かれる。**はい、自分で作りました** を選ぶと、同じウィンドウでライセンスを選び、作成者（1 行に 1 人）と著作権の表示（例：© 2026 A 高校 国語科）を書ける。ライセンスは次の 4 つから選ぶ。

- **CC BY 4.0：** 名前を表示すれば、だれでも使ったり手を加えたりできる。迷ったらこれ
- **CC BY-SA 4.0：** 手を加えたものも同じライセンスで公開する
- **CC BY-NC 4.0：** 営利の目的には使えない
- **ライセンスを付けない：** すべての権利を留保する

:::{figure} images/rights-first-save.png
:label: fig-first-save
:alt: このファイルは、あなたが作ったものですか のウィンドウ。はい を選ぶと、ライセンスの 4 つの選択肢、作成者、著作権の表示の欄が出る
初めて保存するときの問い
:::

あとから変えるときは、**ファイル ▾ → ファイルの情報…** を開く。タイトル・作成者・著作権の表示・ライセンス・クレジットの表示を書き換えて **保存** を押すと、次にファイルを保存したときにファイルの中に入る。ライセンスの一覧にないものは、**その他** を選んで SPDX の名前（例：CC-BY-4.0、MIT）で書く。作業フォルダで作業しているときは、`egatari.json` の `metadata` に書かれる。

:::{figure} images/file-info-panel.png
:label: fig-file-info
:alt: ファイルの情報のパネル。タイトル、作成者、著作権の表示、ライセンス、クレジットの表示の欄と、保存のボタン
ファイルの情報…のパネル
:::

ほかの人の Egatari ファイルを Studio で開いて直そうとすると、Studio は最初に、そのファイルのライセンスと権利者の表示を見せる。改変を認めないライセンス（Creative Commons の ND など）のときは、確認のチェックを入れるまで編集を始めない。

ほかの人のファイルを直して初めて保存するときは、同じ問いで **いいえ、ほかの人のファイルを直しています** を選び、自分の名前（学校名など）と、直した内容を書く。ファイルの情報の作成者の後に「編集：名前（内容）」と出て、だれが直したかが分かる。元の作成者・著作権・クレジットは、保存しても消えない。

v0.6.18 までの Studio では、**ファイルの情報…** は見るだけで書き込めない。そのときは、作業フォルダの `egatari.json` の `metadata` に書く（例：`"license": "CC-BY-4.0"`、`"copyright": "© 2026 A 高校 国語科"`、`"creators": ["A 高校 国語科"]`）。

:::{figure} images/portable-rights.png
:label: fig-rights
:alt: このファイルを編集しますか のウィンドウ。タイトル、作成者、著作権、ライセンス、クレジットが並ぶ
ほかの人のファイルを編集する前の確認
:::

(sec-lnwjaw)=
## LMS に載せる（SCORM）

だれが始めて、だれが最後まで見たかを LMS（Moodle など）で知りたいときは、**SCORM** のパッケージにする。

**ファイル ▾ → エクスポート ▸ → LMS 用（SCORM）…** を選び、**ダウンロード** を押す。`○○.scorm.zip` ができるので、Moodle なら **活動またはリソースを追加する → SCORM パッケージ** で追加する。保存していない変更があるときは、先に保存するよう知らせが出る。

LMS には、始めた・完了した・どこまで進んだか・学習した時間が記録される。既定では、すべてのステップを再生するか、本（本のないファイルは台本）で読んだときに「完了」になる。ウィンドウに、いつ完了になるかが出る。

ファイルに **確認問題**（「予想と答え」などのパーツの問い）があれば、ウィンドウの **確認問題** で、完了の条件にするかを選べる。

- **完了の条件にしない：** 問いに答えなくても、上の決まりで完了になる
- **すべて答えたら完了：** すべての問いに答えたときに完了になる
- **すべて正解したら完了：** すべての問いに正解したときに完了になる

確認問題に答えると、正解した割合が点数として LMS に記録される。合格・不合格は記録しない。答えはファイルの中にあり、学習者の端末で判定するので、ファイルの中身を見れば分かる。確認問題は理解を確かめるためのもので、試験には使えない。成績を付けるときは、LMS の小テストを使う。

:::{figure} images/scorm-dialog.png
:label: fig-scorm
:alt: LMS 用（SCORM）にエクスポートのウィンドウ。説明、完了の決まり、確認問題の選択、キャンセルとダウンロードのボタン
LMS 用（SCORM）にエクスポートのウィンドウ
:::

ふつうに配るだけなら、SCORM は要らない。再生専用のファイルを LMS に「ファイル」として載せればよい。そのときは、表示を「ダウンロード」にしておく。

## 動画にする

動画の置き場所（YouTube など）に載せたいときは、MP4 の動画にする。動画は Studio の中では作らず、Google Colab で作る。

1. **ファイル ▾ → エクスポート ▸ → 動画（MP4）にする…** を選ぶ。保存していない変更があれば、**保存して Colab を開く** になる
2. 開いた Colab で、CPU のランタイムを選び、「すべてのセルを実行」を押す
3. Egatari ファイルをアップロードすると、`full.mp4` がダウンロードされる。章が 2 つ以上あれば、章ごとの動画もできる

動画には、ファイルに入っている音声がそのまま使われる。音声の更新が必要なステップがあると、ウィンドウにその数が出るので、先に第 3 章のとおり作り直しておく。

Egatari ファイルのまま配れば、動画にしなくても再生できる。動画は、動画の置き場所に載せるときだけでよい。

## 発表する：発表者ビューとしおり

教室や会場で映すときは、保存した Egatari ファイルをブラウザで開く。

1. `p` で**発表者ビュー**を開く。発表者ビューは、発表する人の画面に残る
2. 聞き手のウィンドウをプロジェクターの画面へ移し、`f` で全画面にする
3. 発表者ビューで進める。キーのほかに、今のスライドの下の **前へ**・**次へ** のボタンでも進められる

前へ・次へのボタンは、クリックでも指やペンでも押せる。iPad を Sidecar で Mac の 2 つ目の画面にし、そこに発表者ビューを置けば、Apple Pencil で送れる。

`b` を押すと**暗転**する（聞き手の画面が真っ黒になる）。話に集中してもらいたいときに使い、もう一度 `b` で戻る。暗転の間は、前へ・次へを押しても暗転が終わるだけで、ステップは進まない。

**しおり**は、発表の途中で特定のスライドへすぐ飛ぶための印だ。使い方は 2 つある。

- 本編の要所（まとめの図、結果の表など）に付けておき、質疑でその図をもう一度見せる
- 質疑で見せ直したい材料を付録のスライドにまとめ、その扉に付けておく

スライド一覧で選んで **しおりを付ける…** を押すと、名前の欄にはそのスライドの見出し（20 字まで）が入っている。そのままでよければ **付ける** を押す。字を打てば、入っていた名前と置き換わる。名前は、飛んだ先に何があるかが分かるもの（例：「付録」「結果の表」）にする。ほかのスライドのしおりと同じ名前になるときは、後ろに番号が付く。

発表のとき、ツールバーと発表者ビューにしおりのボタンが出て、押すとそのスライドへすぐ飛ぶ。飛んだ先では、スライドの中身がすべて出た状態になる。**元の位置に戻る** か Backspace で、飛ぶ前の所へ戻る。しおりが多くてツールバーに入りきらないときは、名前のボタンが 1 つの **しおり ▾** にまとまり、押すと名前の一覧が開く。発表者ビューには、名前のボタンがそのまま並ぶ。

v0.6.19 までの Studio では、しおりの名前の欄には「質疑用」が入っていた。発表者ビューの前へ・次へのボタンと **しおり ▾** は v0.6.20 からだ。
